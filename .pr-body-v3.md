# v3: offline pastcasting harness + Kalshi longshot guard + monitoring v2

Layers the v3 operating system on top of the v2 calibrated pipeline (PR #1) and Gemini Antigravity's lifecycle baseline (already on `main`). The locked thesis (`docs/V3_OFFLINE_HARNESS.md`) is **train the operating system, NOT the model**: no fine-tuning, no deep RL, no broad crawl, no multi-agent debate. Calibrate the meta-system against historical resolved markets, freeze the best simple variant as the default submission strategy, layer Hedge-style expert weights on top.

## What lands in this PR

### New modules

- `forecasting/market_blend.py` — Kalshi-paper-informed rules:
  - `kalshi_longshot_guard` — if `p_market < 0.10`, weak LLM evidence can't push us up by more than 0.05 unless source_quality > 0.7 AND model_agreement > 0.7. Direct response to the >60% loss finding on sub-$0.10 contracts.
  - `favorites_no_shrink` — if `p_market > 0.85` and LLM is lower, blend 70/30 toward market instead of shrinking toward 0.50.
  - `longshot_proximity` — ramp function wired into `risk.required_edge` so longshots need a fatter edge to clear.
  - `credibility(source_quality, model_agreement, horizon_weight)` — actuarial credibility-weighted logit blend.
  - `full_blend` composer = longshot_guard → credibility blend → favorites_no_shrink.
- `forecasting/source_scoring.py` — credibility hierarchy (official > primary > news > analysis > blog > social), staleness penalty with horizon-aware half-life, ensemble across sources, source_disagreement metric.
- `forecasting/bidirectional.py` — `combine(p_yes, p_no) = 0.5 * (p_yes + (1 - p_no))` per Prophet Arena ablation (4 of 5 models improved). Gate function `should_bidirectional` only triggers near threshold / high notional / sources-conflict.
- `forecasting/expert_pool.py` — Hedge-style multiplicative weight updates. `weight_i ∝ exp(-eta * mean_brier_i)`. Initialized from offline-eval Brier scores. Online updates DISABLED by default pending organizer-rule confirmation.

### Evaluation layer

- `evaluation/brier.py` — Brier, Brier skill score, Murphy decomposition, alpha-vs-market.
- `evaluation/ece.py` — Expected Calibration Error, Maximum Calibration Error, reliability-diagram bins.
- `evaluation/returns.py` — Trade dataclass, simulated_return, Sharpe, `pnl_by_price_bucket` (the Kalshi-style diagnostic).
- `evaluation/no_leakage_check.py` — strict gate; refuses to score if any source's `published_at > forecast_time`. Required before every offline eval.

### Offline harness

- `offline/dataset_schema.md` — canonical JSONL shape.
- `offline/sample_tasks.jsonl` — 12 synthetic events across 6 domains, including sub-$0.10 longshots and >$0.85 favorites to exercise the Kalshi guards.
- `tools/evaluate_offline.py` — runs the **8 strategy variants** against the dataset: `market_only`, `gpt55_no_retrieval`, `gpt55_with_sources`, `gpt55_bidirectional`, `gpt55_plus_opus_review`, `market_blend`, `calibrated_ensemble`, `rl_lite_expert_pool`. Scores on Brier, ECE, BSS-vs-market. Emits markdown + HTML + JSON reports.
- `tools/check_compliance.py` — pre-submission gate (required files, no hardcoded keys, pinned deps, risk constants declared, no forbidden files, no banned phrases, correct author email).
- `scripts/run_offline_eval.py` — orchestrator: no-leakage check → 8-variant eval → reports.

## What this PR deliberately does NOT do

- No model fine-tuning. No deep RL. No broad web crawl.
- No multi-agent debate.
- No model decides trade size (code computes; model only gives probability + uncertainty).
- No change to the locked risk constants (`EDGE_THRESHOLD=0.08`, `MAX_TRADES_PER_TICK=3`, etc.).
- No live online-learning updates (frozen pretrained weights until organizer rules clarify whether mid-evaluation updates are allowed).
