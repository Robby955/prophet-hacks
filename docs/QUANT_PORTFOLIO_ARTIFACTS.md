# Quant portfolio artifacts

The Prophet Hacks work doubles as a quant-portfolio piece. The artifacts
listed below should make Rob's quant-portfolio case for him: calibration
discipline, risk management, engineering rigor, and decision documentation.

Each entry has: format, target audience, priority, and timing.

---

## 1. Submission repo on GitHub

- **Format:** `Robby955/prophet-hacks`. Private during sprint, flipped to
  public post-event with Rob's explicit go-ahead.
- **Audience:** recruiters, hiring engineers, fellow quants.
- **Priority:** P0. This is the artifact everything else points back to.
- **Timing:** repo created at `gh repo create` step in the
  pre-event checklist. Made public after the eval window closes AND after
  Rob has sanity-checked the trace contents for anything sensitive.
- **Content bar:** pinned deps, typed Python, JSONL traces, idempotency,
  hard caps as code constants, decision log, runbook, retrospective.

## 2. DECISIONS.md as the showcased decision log

- **Format:** the existing `docs/DECISIONS.md` plus new entries appended
  through the sprint.
- **Audience:** anyone evaluating Rob's judgment. Quant interviewers love
  documented trade-offs.
- **Priority:** P0. Maintained continuously, not produced at the end.
- **Timing:** every decision during the sprint adds a section. After the
  event, polish ordering and add cross-links.
- **Content bar:** each decision has the rationale (the "why"), not just
  the rule (the "what"). The 7 seed entries already follow this format.

## 3. Performance report (plots and tables)

- **Format:** PNGs in `reports/<slug>/` plus a `summary.json` per slug.
  Generated by `scripts/build_results_report.py` after the eval window.
- **Audience:** technical readers; recruiters who care about
  calibration plots and bankroll curves.
- **Priority:** P1.
- **Timing:** post-event, once `trace/<slug>/*.jsonl` files contain real
  decisions across many ticks.
- **Content bar:** calibration plot (predicted vs realized), per-market-
  class Brier, bankroll curve, edge distribution, skip-reason breakdown,
  summary stats.

## 4. Post-event retrospective writeup

- **Format:** markdown filled in from `docs/POST_EVENT_RETROSPECTIVE_TEMPLATE.md`.
- **Audience:** Rob (most importantly), then anyone who reads the repo.
- **Priority:** P1.
- **Timing:** within 7 days of the eval window closing.
- **Content bar:** three things that worked, three that did not, three
  concrete improvements for next sprint. Real Brier numbers vs both
  random and market-implied baselines.

## 5. Code quality

- **Format:** typed Python (`from __future__ import annotations`),
  pinned deps, a small test suite once it lands, optional `pyproject.toml`
  if we move off `requirements.txt`.
- **Audience:** any engineer skimming the repo.
- **Priority:** P1.
- **Timing:** during sprint where it does not cost speed; tightened
  post-event.
- **Content bar:** modules import cleanly, no banned phrases in code
  comments, hard caps live in `risk.py` constants not yaml-only.

## 6. Long-form blog post or research note draft

- **Format:** ~2000-3000 words. Sections: problem statement, agent
  architecture, calibration discipline (Brier-focused thinking),
  multi-model agreement gate (if shipped), risk management, results,
  lessons. Drafted in a markdown file under `docs/` or pushed as a
  separate GitHub Gist.
- **Audience:** broader audience including non-quant engineers. Doubles
  as a portfolio piece for technical-blog signals.
- **Priority:** P2.
- **Timing:** 1-3 weeks post-event.
- **Content bar:** real numbers, real anti-claims (here is what did not
  work and why), reproducibility receipt at the bottom.

## 7. Reproducibility receipts

- **Format:** README "Quickstart" section with one-command run instructions,
  pinned package versions, and a single example trace that anyone can
  regenerate.
- **Audience:** evaluators who will actually try to run the thing.
- **Priority:** P1.
- **Timing:** during sprint (already partly done in README), polished
  post-event.
- **Content bar:** a clean clone + venv create + `pip install` + one
  command should run a smoke tick end to end. No "first install these
  six undocumented tools" steps.

## Quant-portfolio framing

When the dust settles, the explicit value-prop for a recruiter is:

- **Calibration discipline.** Bucketed probabilities, Brier-focused
  evaluation, equivalence-testing background from the ICML 2026 work.
- **Risk management.** Kelly-aware sizing, hard caps as code constants,
  skip-by-default behavior, idempotency keys on every trade intent.
- **Engineering rigor.** Pinned deps, JSONL traces, append-only experiment
  log, retrospective discipline, dedicated runbook.
- **Decision documentation.** Every non-obvious choice has a rationale
  in `DECISIONS.md`. Quant interviewers ask "why" more than they ask
  "what" — this is the artifact that answers them.
