A fresh repo for portfolio/career use, separate from `Robby955/prophet-hacks`.
The original repo flips public for Devpost judging but keeps the full
weekend commit history (which is fine — it shows real engineering, but
isn't curated for a hiring audience).

This plan is the cut-down. Pick the showcase repo name later (working
title: `Robby955/oracles-forecasting` or `Robby955/the-oracles`).

## When

After Prophet Hacks closes (Sunday 2026-05-17 ~17:00 CT) and after the
2-week PA scoring window ends (~2026-05-31). Until then, the existing

## Why not just clean the existing repo

- 80+ commits with weekend-paced messages, agent-coordination noise,
  Codex chatter, and several "fix typo" follow-ups. Not bad, but reads
  as hackathon work rather than portfolio work.
- Some commits reference Codex, AGENT_STATUS.md, internal worktree
  paths, and other coordination ephemera that's irrelevant to a reader.
- The fresh-repo version can land as 1 well-scoped initial commit plus
  any follow-ups for post-event improvements (FutureSim chronological
  replay, confidence-aware critique, etc).

## How (mechanically)

1. Create fresh empty repo `Robby955/the-oracles` (or final name) on GitHub.
2. Locally:
   ```bash
   git init the-oracles && cd the-oracles
   git remote add origin git@github.com:Robby955/the-oracles.git
   ```
3. Copy curated files in. Pin file list above.
4. Single initial commit:
   ```
   feat: initial — calibrated forecasting agent for Prophet Arena

   - Pipeline: Brave + Opus 4.7 + Kalshi-paper longshot floor
   - Brier 0.0378 (n=26, sample-resolved) and 0.1224 (n=1200, scale set)
   - Paired-bootstrap CI promotion gate; backtest-leakage audit
   - Two negative results (adversarial critique, ablation rejects)
   ```
5. Push to main. Set repo description + topics on GitHub.
6. Run `./scripts/full_check.sh` against the new clone to confirm tests
   pass and smoke-imports work in isolation from the hackathon repo.

## Auth on /dashboard — clarification (Rob's question)

The `/dashboard` PIN is **not** code secrecy. It exists because:

1. The page exposes `/demo/start` which costs ~$0.05/run (Brave + Opus).
   Without auth, anyone can spam-click "Run live demo" and burn budget.
   The PIN is rate-limiting by friction.
2. The page also shows the live prediction trace store (predictions
   served, evidence URLs, model rationales). Those traces are technically
   safe to publish (no PII, no PA payloads with score-sensitive content),
   but during the active 2-week scoring window we want to be cautious
   about exposing live PA-call traces in case PA's rules around that
   change. Easier to gate first, ungate later.
3. The PIN is **not in this repo**. It's set as a Railway env var. The
   showcase repo doesn't need the auth code path at all — drop the
   `_require_dashboard_auth` middleware in the curated version and let
   the showcase deploy be fully public (no demo button, just the static
   research pages).

Post-event, both `/observatory` and `/review` can also open up. The PIN
infrastructure stays in the original repo for the live agent; the
showcase repo's auth-free variant is for hiring conversations.
